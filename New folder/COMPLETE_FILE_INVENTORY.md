## 🎯 HOW EVERYTHING WORKS TOGETHER

### **Startup Flow**
```
1. User runs: npm start
   ↓
2. index.js runs, loads config.json and .env
   ↓
3. index.js validates all required settings
   ↓
4. index.js creates Discord client
   ↓
5. index.js loads all commands from /commands
   ↓
6. index.js loads all events from /events
   ↓
7. index.js connects to Discord (using token from config)
   ↓
8. index.js starts dashboard server (port 3000)
   ↓
9. Bot goes ONLINE - ready to accept commands
```

### **User Interacts with Bot**
```
User: /case create "Investigation Title"
   ↓
Discord API → events/interactionCreate.js
   ↓
routes to /commands/case/index.js
   ↓
command calls modules/database.js to save case
   ↓
modules/logger.js logs the action
   ↓
modules/alerts.js sends notification to alert channel
   ↓
modules/backup.js schedules backup (if enabled)
   ↓
Bot responds with confirmation to user
```

### **Scheduled Backups**
```
Every hour or on shutdown:
   ↓
modules/backup.js runs
   ↓
Reads all JSON from /data folder
   ↓
Creates timestamped backup copy
   ↓
Stores in /backups folder
   ↓
Cleans up old backups (keeps last N)
```

### **Dashboard Access**
```
User opens: https://localhost:3000
   ↓
dashboard/server.js handles request
   ↓
Shows login form (password required)
   ↓
modules/dashboardAuth.js validates password
   ↓
Creates session token
   ↓
User can now:
  - View statistics
  - Manage cases
  - View logs
  - Configure bot
  - All actions logged for audit
```

### **Security Event Processing**
```
Someone joins a server:
   ↓
Discord sends guildMemberAdd event
   ↓
events/guildMemberAdd.js processes
   ↓
modules/serverBlacklist.js checks if user on blocklist
   ↓
modules/serverGuard.js checks server reputation
   ↓
modules/surveillance.js logs the join
   ↓
If suspicious:
  modules/alerts.js sends alert to staff
  modules/logger.js records event
  If severe: modules/kelplerProtocol.js may start investigation
```
